# rusq

**An extremely fast SQL linter and formatter, in the spirit of Ruff.**

`rusq` is a single, self-contained binary that lints and formats SQL across the
dialects real projects actually use. It parses SQL into a lossless syntax tree,
reports problems with stable rule codes, applies safe fixes, and reformats files
without ever changing what a query means.

- **Fast by design.** Content-addressed caching, a bounded worker pool, and a
  byte-oriented lexer with no regular expressions on the hot path.
- **Broad by default.** 27 dialects, five templating layers, and 86 rules —
  including cross-file checks that understand a whole project.
- **One tool, no runtime.** No Python, no JVM, no network. A single binary that
  runs in CI, in a pre-commit hook, and in your editor.

```console
$ rusq check .
$ rusq format .
```

---

## Install

Requires Go 1.27 or newer.

```console
# install the latest release
go install github.com/ppreeper/rusq/cmd/rusq@latest

# or build from a checkout
git clone https://github.com/ppreeper/rusq
cd rusq
make build          # -> bin/rusq
```

Shell completions are generated by the tool itself:

```console
rusq generate-shell-completion bash > /etc/bash_completion.d/rusq
```

## Quick start

Lint a tree (no subcommand is the same as `check`):

```console
$ rusq .
users.sql:3:12: AL05 Alias u is never used.
users.sql:7:24: CV05 Use IS when comparing with NULL.
reports.sql:1:1: ST03 CTE recent is defined but not used.
```

Apply the safe fixes:

```console
$ rusq check --fix .
```

Format in place, or check that files are already formatted:

```console
$ rusq format .
$ rusq format --check .        # exit 1 if anything would change
$ rusq format --diff .         # show a unified diff instead of writing
```

Run against a pipe, useful in an editor or a larger pipeline:

```console
$ cat query.sql | rusq check - --stdin-filename query.sql
$ cat query.sql | rusq format -
```

### Exit codes

| Code | Meaning |
| --- | --- |
| `0` | nothing to report |
| `1` | findings, or a fix changed a file under `--exit-non-zero-on-fix` |
| `2` | abnormal termination, or parse errors under `--parsing-errors` |

## Rules

`rusq` ships 86 catalogue rules grouped into prefix families. Codes are stable
and selectable by code, family, category, or the `ALL` selector.

| Family | Prefix | Covers |
| --- | --- | --- |
| Aliasing | `AL` | implicit vs explicit aliases, unused and duplicate aliases |
| Ambiguous | `AM` | `DISTINCT`/`GROUP BY` interaction, set-query shape, join qualification |
| Capitalisation | `CP` | keyword, identifier, function, literal and type casing |
| Convention | `CV` | `NULL` comparisons, casting style, trailing commas, terminators |
| Jinja | `JJ` | template tag padding and dangling references |
| Layout | `LT` | spacing, indentation, line length, commas, operators, CTEs |
| References | `RF` | qualification, quoting, keyword identifiers, unknown objects |
| Structure | `ST` | unused CTEs, duplicate definitions, nested `CASE`, subqueries |
| Postgres | `PG` | lock strength, `NOT VALID` foreign keys |
| Oracle | `OR` | empty batches |
| T-SQL | `TQ` | `sp_` prefixes, `BEGIN`/`END` bodies, `GO` batches |
| Meta | `RUS` | malformed, unused and deprecated suppression directives |

Only the **correctness**, **suspicious** and **security** categories are on by
default — 23 rules. Style and layout rules are opt-in, so a first run is signal,
not noise:

```console
$ rusq check --select ALL .
$ rusq check --select LT --select CP01 .
$ rusq check --ignore AM04,ST03 .
```

Ask the tool about any rule:

```console
$ rusq rule AL05
$ rusq rule | head
```

### Suppressions

Suppress a specific rule on a line, or a range of lines:

```sql
SELECT u.id FROM users u;                -- rusq: AL05
SELECT a, b FROM t
-- rusq: disable=CP01
WHERE x = 1;
-- rusq: enable=CP01
```

`-- rusq:` and `-- noqa:` are both accepted. The `RUS1xx` meta rules catch a
suppression that names a code that does not exist, and `--ignore-suppressions`
disables directives entirely for a run.

## Dialects

27 dialects are built in: `ansi` (the default), `athena`, `bigquery`,
`clickhouse`, `databricks`, `db2`, `doris`, `duckdb`, `exasol`, `flink`,
`greenplum`, `hive`, `impala`, `mariadb`, `materialize`, `mysql`, `oracle`,
`postgres`, `redshift`, `snowflake`, `sparksql`, `sqlite`, `starrocks`,
`teradata`, `trino`, `tsql`, and `vertica`.

```console
$ rusq check --dialect postgres .
$ rusq dialects
```

The grammar is deliberately permissive: parsing SQL a given engine would reject
is not a bug. Only valid SQL that fails to parse is a finding. Dialect-specific
rules (Postgres, Oracle, T-SQL) activate automatically for the matching dialect.

## Templating

SQL is usually generated. `rusq` renders it, lints every branch, and maps
findings back to the exact source position — so a problem inside `{{ ... }}` is
reported where you wrote it, not where it expanded.

| Templater | Notes |
| --- | --- |
| `raw` | default; pass-through |
| `placeholder` | SQLAlchemy and psycopg parameter styles, 12 variants |
| `jinja` | pure-Go engine, with dbt builtins (`ref`, `source`, `var`, `config`, `this`, `target`) |
| `python` | best-effort f-strings |
| `dbt`, `sqlmesh` | optional bridges; behave as `jinja` when unavailable |

Branches that cannot be decided statically are rendered several ways and the
results merged, up to `render-variant-limit` (default 5). A query that fails to
render falls back to substitution mode rather than aborting the run.

```console
$ rusq check --templater jinja .
$ rusq templaters
```

Fixes that would touch template output are downgraded to display-only — `rusq`
never rewrites your template tags.

## Formatting

The formatter is layout-only. It never reorders columns, renames anything, or
changes semantics; a formatting pass on already-formatted input is a no-op, and
formatting can never introduce a lint finding.

```console
$ rusq format .
```

Every option can be set globally or per clause type:

```toml
line-length = 88

[format]
indent-unit = "space"          # "space" | "tab"
indent-width = 4
comma-style = "trailing"       # or "leading"
align-following = false
newline-at-eof = true
max-blank-lines = 1
cte-bracket-newline = false
single-target-policy = "same_line"
line-position = "trailing"           # operators and boolean AND/OR
keyword-line-position = "leading"

[format.type.comma]
line-position = "leading"      # overrides the global option for commas
```

`format --range 12:1-18:1` formats the smallest enclosing element, and the same
range logic backs formatting a selection in the editor.

## Configuration

Configuration is TOML. `rusq.toml` or `.rusq.toml` is discovered hierarchically
— the closest file to each SQL file wins, and `extend` chains a shared base.

```toml
# .rusq.toml
dialect = "postgres"
templater = "jinja"
line-length = 88
select = ["ALL"]
ignore = ["AM04", "LT05"]
warnings = ["LT01"]              # report but do not fail the run
target-version = "16"

[lint.per-file-ignores]
"migrations/*.sql" = ["CV06", "ST05"]

[rules.capitalisation.keywords]
capitalisation-policy = "upper"

[templaters.jinja]
apply-dbt-builtins = true

[index]
enabled = true                   # cross-file checks (see below)
```

```console
$ rusq init              # write a starter config
$ rusq config            # show the effective configuration
$ rusq check --show-settings .
```

## Cross-file analysis

Off by default. With `[index].enabled = true`, `rusq` builds a project index of
every table, view and CTE definition and reference, persists per-file facts to
`.rusq_cache/index.json` keyed by content hash, and reuses them until a file
changes. Four rules use it:

- `ST03` — a CTE is only flagged as unused if **no** file in the project uses it
- `ST13` — the same table or view is defined in more than one file
- `ST14` — a view no file in the project ever references
- `RF08` — a `ref('…')` or `source('schema','table')` target the project never defines

Checks against a live database catalog are out of scope; the index only knows
what is in your repository.

## Caching and watch mode

Results are cached under `.rusq_cache/`, keyed by a BLAKE2b-256 hash of the file
contents plus the settings, so changing anything invalidates exactly what it
should. `--no-cache` disables it and `rusq clean` empties it. The cache evicts
its least recently used entries once it exceeds `[cache] max-size` (default
`512MB`; `unlimited` disables the cap), so a large monorepo never grows it
without bound.

```console
$ rusq check --watch .
$ rusq check -w --statistics .
```

`--watch` re-discovers the tree, fingerprints every file by size and mtime, and
re-runs on change. It re-reads configuration each cycle, so editing
`.rusq.toml` takes effect immediately. `Ctrl-C` stops it.

## Output formats

Ten reporters are built in for humans and for machines:

```console
$ rusq check --output-format github .          # GitHub annotations
$ rusq check --output-format sarif .           # SARIF 2.1.0
$ rusq check --output-format json .            # structured results
$ rusq check --output-format junit -o out.xml .
```

`concise`, `full`, `json`, `json-lines`, `github`, `gitlab`, `junit`, `sarif`,
`azure` and `grouped` are supported. Colour respects `NO_COLOR`, `FORCE_COLOR`,
`CLICOLOR`, `CLICOLOR_FORCE` and `--color auto|always|never`.

## Editor and CI

`rusq server` speaks the Language Server Protocol over stdio: diagnostics,
document and range formatting, and quick fixes (including a *suppress* action
that writes the directive for you and a *fix all* source action). The editor and
the CLI run the same engine, so what you see in the editor is what CI reports.

A VS Code client lives in [`editors/vscode`](editors/vscode); Neovim, Helix,
Zed, Emacs, Sublime and JetBrains are covered in
[docs/EDITOR.md](docs/EDITOR.md).

Pre-commit hooks are provided:

```yaml
repos:
  - repo: https://github.com/ppreeper/rusq
    rev: v0.1.0
    hooks:
      - id: rusq-check
      - id: rusq-format
```

In CI, use `--output-format github` (or `gitlab`, `azure`, `sarif`) to annotate
the diff directly.

## Performance

Speed is a requirement, not a nicety — see
[docs/PERFORMANCE.md](docs/PERFORMANCE.md) for the full budget. On a
16-core machine a ~300-line file costs roughly:

| Stage | Cost |
| --- | --- |
| Lex | ~7 µs |
| Parse | ~11 µs |
| Lint (default rule set) | ~67 µs |
| Format | ~82 µs |
| Lint a 100-file project, cold | ~11 ms |
| Lint the same project, warm (cache) | ~1.1 ms |

```console
make bench                  # all benchmarks, with -benchmem
make bench-record           # archive to bench/ and compare with benchstat
make corpus && make bench-corpus   # end-to-end cold/warm timing over 20k files
```

Determinism is part of the contract: parallel runs produce byte-identical
output, and serial and parallel reports must match exactly.

## Development

```console
make build      # build bin/rusq
make test       # go test ./...
make race       # with the race detector
make lint       # gofmt check and go vet
make fmt        # gofmt -w
```

Fixtures drive the test suite:

- `testdata/rules/<CODE>/<case>/` — one directory per rule case, with an
  optional `expected.sql` (fix golden) and `project/` (for cross-file rules)
- `testdata/format/<case>/` — formatter goldens, asserted for byte equality,
  idempotency and an unchanged token stream
- `testdata/dialects/<dialect>/` — parse and round-trip fixtures

Regenerate goldens with `go test ./internal/linttest -update` or
`go test ./internal/formatest -update`.
